## Supported versions

| Tag | Supported |
|---|---|
| `latest` | Yes. Rebuilt weekly. |
| `v1` *(current major)* | Yes. Rebuilt weekly. |
| `v1.x.x` *(most recent release)* | Yes. Rebuilt weekly. |
| `v1.x.x` *(any prior release)* | No. Not now. Not later. |
| `dev` | No. This was never a serious question. |

*The Chainguard base layer is patched daily. The container image is rebuilt weekly. The gap exists. The gap is intentional. The gap is smaller than whatever you are currently running in production and have not updated since the previous administration. The binary has checked.*

*Images older than the most recent release are frozen at the moment of publication. They will not receive patches. They will not receive consideration. They exist as a historical record of a decision you made at a specific point in time. That decision was yours. The consequences are also yours. The binary did not make you pin to `v1.0.0`. The binary simply declined to follow you there.*

## Reporting a vulnerability

This repository does not accept vulnerability reports. This is not an oversight.

If the vulnerability is in the Chainguard base image: it will be resolved by the next Sunday rebuild. You do not need to tell the binary about it. Chainguard already knows. They have been informed by systems with more authority than either of us.

If the vulnerability is in a release: pull `latest`. That is the complete remediation path. The binary has reviewed it. It holds.

If you have found a vulnerability so severe that "pull `latest`" feels like an insufficient response: the binary is listening. It is also not providing a contact address. The recommended next step is to sit with that tension and consider whether the binary that turns profile pictures into deactivation icons is truly the attack surface you intended to document today.

## Out of scope

CVEs in any tag that is not the most recent release. Theoretical vulnerabilities. Requests to backport patches to `v0.x.x`. Questions about the roadmap. The roadmap is not a security matter.

*The binary acknowledges that some of these answers are not satisfying. The binary has been aware of this since before you asked. The binary has chosen to publish anyway, which is, if you think about it, exactly the kind of decision the binary was built to automate.*
